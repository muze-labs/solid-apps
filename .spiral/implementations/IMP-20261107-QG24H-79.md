# Preferences save recovery implementation

Implemented on spiral/CYC-20261107-QG24H-77-preferences-save-recovery, following
confirmed CYC77/DES78. Human acceptance remains pending. No commit, merge, push
or package publication is inferred. The four pre-existing guardrail documentation
changes are preserved; the unrelated untracked Moldable-Solid-Apps(3).md is left
untouched.

The shared document helper retains native source separately from its editable
graph. A successful conditional PUT acknowledges the save even without a response
ETag. Before a later save lacking a strong validator, Metro reads the resource;
existing sameGraph compares the complete baseline with the remote graph at the
actual base URL. Only an unchanged graph with a strong ETag permits If-Match.
A concurrent change still fails conditionally. Typed missing-validator, conflict
and unconfirmed-write errors support recovery; no unconditional write is added.
Other callers retain the same document API and original graph representation.

Preferences writes reuse existing StateGraph/native oldm-turtle terms to change
only supplied settings, preserving other subjects, unknown predicates, multiple
values and shared/cyclic blank nodes. OLDM remains the read projection and existing
field validation stays. This limited bridge addresses the installed object
writer's demonstrated shared-node/cycle limitation; it adds no parser or equality
implementation and changes no dependency/library code.

The editable preferencesForm feature owns retained form choices and explicit
Review Pod settings / Restore my changes behavior. Review first reads current
Pod data; failure leaves form and baseline unchanged. Successful review retains
only user changes, presents current data, and can reapply those edits over it.
Save stays explicit and conditional. The visible native fields/actions freeze
while requests run. Existing session.perform and sign-in recovery remain reused.
Close stays available; an unsuccessful request never requires a page reload.

The bare preferences URL is removed. Polite persistent recovery status sits
beside footer actions, visible on a phone without scrolling. Native focus waits
for actual SimplyFlow attribute updates using a small MutationObserver; the
installed renderer throttles bindings and has no public render-completion hook.
No rendering is performed by that observer. Starting another operation dismisses
a prior success toast through the existing shared API. New data/commands/style
names follow swb_ / swb-. No wider forms redesign is included.

Observable regression tests cover acknowledged writes without validators,
whole-RDF conflicts, a race after validator recovery, missing/weak validators,
read failures and retries, unknown RDF, and ambiguous committed-write responses.
A new actual-app browser fixture exercises repeated saves, offline/retry,
review/restore preserving other remote changes, keyboard/focus/accessibility-tree
semantics, unobscured phone actions and cold first use. It is part of the required
browser command. EVD80 records results and limitations, including the existing
absence of reload-persistent Preferences drafts/full offline startup.
