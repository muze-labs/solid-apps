# Browser-local managed workspace and picker

This semantic revision replaces the Node relay/client/panel with Launcher-owned
windows and private MessagePorts. The prior implementation remains immutable
history. The effective cause is the revised managed-workspace design, not the
superseded server design.

`WorkspaceBroker` binds origin/window/instance, owns reconnect keys and explicit
route policy, and checkpoints per-instance JSON state. `ManagedApp` supplies a
renderer-independent child API with state/restore and capability hooks. Calls
have cancellation, disconnect, timeout and bounded work. Only Launcher requests
browse from explicitly allowed Files instances in this slice.

`WorkspaceState` reuses published Solid Workspace IndexedDB for account-scoped
local caching. Live updates do not PUT to the Pod. A native Turtle document with
one RDF JSON snapshot is prepared while active; unknown RDF remains intact.
Explicit Save & close checkpoints and waits for conditional acknowledgement.
Browser-X attempts prepared keepalive through Metro without interactive login;
local state remains pending because shutdown delivery cannot be confirmed.

Files restores folders, Profile restores subjects, Contacts restores selection
and search. Profile edit drafts restore separately from authoritative RDF.
Launcher retains the app set at workspace shutdown and removes individually
closed instances. Multiple-app restore exposes popup policy recovery. Ordinary
opener is intentional; incompatible COOP and uncooperative apps limit lifecycle
management. No relay deployment or new npm dependencies are required.

SimplyFlow owns rendering. The shared preference adds a workspace document IRI;
old brokerUrl values survive as unknown RDF. Build-time templates remain readable
in View Source, and the full JavaScript graph plus auth callback stays below
200000 gzip bytes per app. Named workspaces and continuous app-data sync remain
out of scope. See broker/README.md for operation and verification limits.
