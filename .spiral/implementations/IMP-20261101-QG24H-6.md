# Browser-local managed workspace and picker

Native RDF persistence now implements DES25 under SRC24's explicit no-migration
decision. DEF18 is corrected on this cycle branch. The prior JSON encoding and
its earlier acceptance/retained defect remain immutable history; no general
JSON-in-Turtle exception is introduced.

This semantic revision replaces the Node relay/client/panel with Launcher-owned
windows and private MessagePorts. The prior implementation remains immutable
history. The effective cause is the revised managed-workspace design, not the
superseded server design.

`WorkspaceBroker` binds origin/window/instance, owns reconnect keys and explicit
route policy, and checkpoints per-instance RDF state graphs. `ManagedApp` supplies a
renderer-independent child API with state/restore and capability hooks. Calls
have cancellation, disconnect, timeout and bounded work. Only Launcher requests
browse from explicitly allowed Files instances in this slice.

`WorkspaceState` reuses published Solid Workspace IndexedDB for account-scoped
local caching. Live updates do not PUT to the Pod. A Turtle document with
native workspace/app triples is prepared while active; unknown RDF remains intact.
Explicit Save & close checkpoints and waits for conditional acknowledgement.
Browser-X attempts prepared keepalive through Metro without interactive login;
local state remains pending because shutdown delivery cannot be confirmed.

Files restores folders, Profile restores subjects, Contacts restores selection
and search. Profile edit drafts restore separately from authoritative RDF.
Launcher retains the app set at workspace shutdown and removes individually
closed instances. Multiple-app restore exposes popup policy recovery. Ordinary
opener is intentional; incompatible COOP and uncooperative apps limit lifecycle
management. No relay deployment or new npm dependencies are required.

SimplyFlow owns rendering. The shared preference adds a workspace document IRI;
old brokerUrl values survive as unknown RDF. Build-time templates remain readable
in View Source, and the full JavaScript graph plus auth callback stays below
200000 gzip bytes per app. Named workspaces and continuous app-data sync remain
out of scope. See broker/README.md for operation and verification limits.

## Save-failure recovery correction

FBK11 exposed a missing recovery path after deliberate conflict refusal. The
Launcher now retains operation results across reload, displays them beside the
controls, and checks known conflicts before reserving authentication UI. Local
restoration continues after a failed remote bind/preparation. Review shows local
and freshly fetched Pod snapshots; choosing local saves conditionally against
the reviewed native document. A new 412 invalidates that review. Choosing Pod
replaces/restores the managed session without a PUT. Remote preparation errors
no longer reject the local persistence queue. Native RDF remains authoritative.

## Checkpoint timeout correction

FBK13 exposed the 2.5-second state deadline and missing stale-port recovery. The
client now announces closed-port reconnection, separates restoration/readiness,
and reuses live UI/restoration on same-instance reconnection. Captured channel
identity prevents stale tasks publishing into a replacement port. Launcher uses
a ten-second checkpoint deadline, identifies failures by app name/URL, persists
healthy sibling checkpoints and leaves apps open on failure. Restoration failure
is visible instead of waiting indefinitely. Older clients that cannot guarantee
live-draft preservation are asked to reload rather than automatically replayed.

## PUT acknowledgement without a response validator

FBK15 supplies the actual CSS 205-without-ETag response and corrected authorized
GET with a readable strong ETag. Workspace saving now keeps the conditional
write acknowledgement independently of next-write preparation. It clears the old
validator and retains a target-scoped acknowledged snapshot baseline locally.
A later explicit write refreshes the native resource and validator without
false conflicts against that same acknowledged snapshot or silent adoption of
a different remote workspace. Actual conflicts, read failures and missing GET
validators remain refusals. Local edits arriving during a PUT stay pending;
ordinary-close saving cannot reuse the old ETag. No Pod configuration or shared
library defaults change. The browser fixture now matches the real 205 pattern.


## Picker activation and built-in Files startup

FBK20 reopens this cycle after manual selection exposes a missing tab switch.
Launcher policy in picker.mjs selects one allowed live provider, reuses a saved
built-in instance or opens built-in Files before awaiting startup. It preserves
grants, reports ambiguity, waits for readiness/cancellation/failure, and binds
invocation to that instance. The generic broker retains route authorization and
only supplies readiness waiting and focus requests; provider/registry policy
stays in Launcher.

Files selection/cancellation requests opener focus and gives explicit manual-
return guidance when the browser refuses. The Chrome fixture verifies cold/warm
Files tab activation and routing; returning to Launcher is advisory and was not
observed in the headless run. Native RDF persistence correction DEF18 stays open;
no new persistence encoding or migration is introduced. Focused tests avoid the
known noncompliant persistence fixtures and serializer.

## Picker return and sign-in popup lifecycle

FBK22 confirms activation into Files and reports failed return plus a likely
orphan authentication callback tab during protected browsing. Launcher now
advertises a random live browsing-context name through its verified opener
offer. Provider response targets that existing named tab during the user's
gesture, checks the returned WindowProxy and keeps advisory focus as fallback.
The hint stays outside restoration identity and persistence. Isolated Chrome
now returns to Launcher after selection and cancellation with no additional tab.

Session authorization now always retains a popup handle before invoking the
published Metro helper, including the cached-ID-token/protected-resource path.
It closes that exact window on success or failure, refuses blocked windows and
preserves noninteractive refusal and library validation. Focused tests use real
discovery/session/popup policy with a client-construction fixture and synthetic
OAuth responses; no real credentials, user Pod or workspace codec are involved.
DEF18 stays Open; this correction changes no persistence format.


## Native workspace, app-state graphs and accepted baseline

SRC24 explicitly requests the correction without migration. WorkspaceState now
persists native current and baseline graphs, typed metadata and local reconnect
keys. The Pod gets only native public workspace/app state. Workspace RDF codec
reuses existing instance and list identities, preserves unknown triples and
rejects malformed scalar/multiple/ordering structures. The raw-triple boundary
uses the installed oldm-turtle parser and a small Turtle emitter to preserve
shared blank nodes, lists, cycles and exact lexical values. Equality uses exact
bounded blank-node isomorphism; ambiguous exhaustion cannot waive a conflict.

Apps exchange Turtle transport text plus an optional verbatim opaque string.
App state subjects are scoped per instance; external IRI references are retained.
Each app owns its full native graph and changes only known fields. Contacts and
Profile share native draft handling, separate from authoritative profile data.
Unsupported graph ownership/sharing edits fail instead of flattening native RDF.
No JSON snapshots or baseline strings are written. Opaque app-state JSON alone
is tested under the explicit narrow experiment.

Use a new native cache, leave development records alone and reject old-format
Pod targets. No migration/import or silent overwrite is implemented. Updated
fixtures exercise the native representation, enabling the full check/browser
suites again. Save acknowledgement, post-205 refresh, pending edits, auth/offline
refusal, conditional conflicts, checkpoint/reconnect and picker/lifecycle
contracts remain covered. DEF18 stays recorded as fixed on the cycle branch;
renewed human cycle acceptance and merge remain separate.


Preparation captures one immutable checkpoint before building its body and
metadata synchronously. A controlled microtask regression first reproduced a
clean acknowledgement paired with an older body; the correction keeps later
edits pending or refuses the stale preparation until a fresh save. This preserves
the same pending-edit contract across preparation and the subsequent PUT.
