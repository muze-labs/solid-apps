# Shared data and UI bundles

## Current implementation

Rollup composes all four apps and the authentication callback in one output
graph. Published Metro/OLDM/Solid Workspace libraries and shared data helpers
are emitted once in shared/data.js. SimplyFlow, SimplySolid and suite views
are emitted in shared/ui.js, which may import data. Each app keeps its own
remaining code; the callback imports data only. App-specific broker and
link-metadata code remains in the relevant app chunk.

Each graph is emitted in readable .js and minified .min.js variants using the
published Rollup Terser plugin. Production HTML references minified app entries
and the callback; npm run dev passes --readable to select the readable graph.
Both variants retain original-source maps and self-contained imports. Function
and class names are preserved, and property-name mangling is not enabled. The
size report contains production apps, readableApps and the selected variant;
the existing strict limit is checked for both variants.

The build selects the existing oldm-turtle composition for app and callback
imports, rejects N3, checks shared-layer boundaries and unresolved imports,
emits readable ES modules/source maps, removes retired generated assets, and
reports complete per-app gzip graphs including the callback. The strict
200000-byte budget remains in force. External dependencies remain npm versions.

The picker and session-popup fixtures use Rollup after esbuild is removed.
Browser checks wait for app initialization, the rendered Profile input and
managed-child reconnection. The shared page-load helper subscribes and checks
readiness in a single browser task. These are test-harness changes; application
rendering, authentication and persistence semantics are unchanged.
