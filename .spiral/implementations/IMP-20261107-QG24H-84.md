# Current-action dispatch implementation

Implemented on verified spiral/CYC-20261107-QG24H-82-current-action-dispatch from
accepted main 473dda5ee37811ec232db575009f55c3f5799819. The maintainer's "agreed"
authorizes the confirmed CYC82 goal after the actual proxy-gap checkpoint; it
is not acceptance, commit, merge, push or publication authorization.

Existing Profile/Preferences widget methods and shell host methods now retrieve
the effective action at invocation. Managed app state/request/cancel/close
callbacks, broker authorization/status/change callbacks, authentication callbacks,
profile persistence/change callbacks, stored lifecycle/capability event handlers,
and scheduled toast actions use the same direct lookup. A multi-file upload's
URL callback also retrieves the action for each later file without replaying
completed writes. Stable listener forwarding functions remain stored for native
removeEventListener; registration ownership itself is unchanged.

The bridge is a local arrow forwarding the original arguments/result to the
supported public actions table. SimplyFlow still supplies context/error behavior.
No shared dispatcher, generic proxy, renderer, override manager, new dependency
or sibling library edit is introduced. An action already running continues;
replacement affects later invocations. Immediate array-query callbacks and
immediately started operations are retained rather than mechanically wrapped.
A disposable Rollup-AST inventory of app/package action references confirms the
remaining captures belong to immediate jaqt pipelines or immediately invoked
run operations, after inspecting the upload callback's asynchronous lifetime.

Design reconciliation records personal overrides last, inspectable component
and app-owned originals, and correct restoration of the raw authored effective
function. It distinguishes runtime actions from source metadata and avoids
re-wrapping bound error-handling callables. Independent future IDE/app histories,
marketplace separation, template notifications and open upstream-version concerns
are recorded without implementing them. Accepted build-time composition and
current readability/library/feature guardrails remain intact.

Four new regression tests exercise current native event delivery/cleanup,
managed callback context/arguments/promises/failures and native-state retention,
scheduled toast replacement/restoration, and later upload callbacks across an
await with byte and conditional-header preservation. The existing actual-app
browser suite now checks already-created host/Preferences/Profile widgets,
events and managed/broker callbacks across all four apps. A real unsaved Contacts
draft and native app state remain unchanged through replacement/restoration.
Original definitions stay inspectable. EVD85 retains all results and limits.

Pending roadmap/assessment/review documentation is preserved on this branch.
The unrelated untracked design/Moldable-Solid-Apps(3).md is untouched. No visual
redesign, persistent override layer, automatic model/template reapplication,
preferences propagation or lifecycle ownership migration is claimed.
