# Session renewal implementation

Implemented on spiral/CYC-20261107-QG24H-67-session-renewal-recovery after the
maintainer's explicit refresh-first design confirmation. Branch was mechanically
verified before implementation and during evaluation. No commit/merge/publication
has been requested.

- solid-app-data authorization.mjs composes Metro core transport with a narrow
  invalid_grant classifier and supported-provider offline authorization/consent.
  It neither exchanges tokens itself nor bypasses issuer/state/nonce/DPoP checks.
  A direct published metro-core dependency records the public API being used.
- connectSession delegates silent renewal to Metro. Typed recovery pauses or
  fails a challenged request appropriately; one-request retry preserves body
  and conditional headers, never replaying the full app operation. An explicit
  authorized GET can renew a session without replacing the app's data or drafts.
  Cached identity no longer controls popup reservation. Shared authorization can
  release a waiting request without an additional popup. Operation counters own
  the shared popup across concurrent perform calls. Request-scoped cancellation
  gates prevent delayed token responses from sending a cancelled write, while
  later retries remain usable.
- solid-app-ui adds an editable per-file sessionRecovery feature, SimplyFlow
  bindings for the contextual notice/dialog, explicit sign-in/cancel, shared
  dialog motion, namespaced commands/fields and success toast. Popups are
  reserved synchronously by explicit Connect/Sign in actions. Native Escape
  cancellation, including non-cancellable CloseWatcher events, releases saving.
- Account restoration suppresses raw sign-in-required status while retaining
  other errors and public content. Storage events reconcile renewal status.
- Preferences can recover a failed initial read without overwriting open edits
  or resetting an existing baseline; Save can recover an initially missing
  baseline in the same operation. Profile/Preferences suppress intentional
  cancellation errors. Existing provider saves remain native RDF
  with conditional-write and conflict protection.
- Authorization contract tests and the real-Metro signed-OIDC browser fixture
  cover silent renewal, revocation, cancel/retry, shared recovery, profile and
  Preferences drafts, unknown RDF and write conflict. The fixture is included
  in npm run test:browser with the existing three suites.

DES69 retains design and limitations; EVD71 records checks and actual outcomes.
No hidden-iframe authentication, account ownership redesign, credential messages,
upstream library edits, links to sibling packages or publication is included.
CYC67 remains Active pending human evaluation/acceptance.


## Live-evaluation toast refinement

The maintainer confirms live sign-in recovery and toast timing, then requests
slide-up entry/downward exit. The shared solid-design toast now uses 300ms native
CSS opacity/vertical transitions. SimplyFlow binds a prefixed closing state;
the lifecycle hides/clears content only after exit. Existing eight-second timing,
hover/focus pause, polite announcement and focus restoration remain. Exiting
content is inert, replacement cancels the old exit, and reduced motion skips the
animation/wait. Installed the-ds 0.2.7 exposes horizontal scale/data-state toast
animations; the suite's vertical presentation and existing lifecycle need the
limited CSS override rather than its automatic horizontal animation.

Shared browser assertions cover rendered entry/exit, delayed removal, focus,
replacement and reduced motion. EVD71 retains checks and actual browser evidence.
The cycle remains Active, without commit/merge authorization.
