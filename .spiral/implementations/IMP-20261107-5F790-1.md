# App-specific Preferences candidate

## Current implementation

Contacts, Launcher and Files provide their own storage section in the shared
Preferences dialog. Profile currently exposes common settings only. The build
composes the app's HTML section into the existing shared template. SimplyFlow
continues to render fields and feedback; native dialog lifecycle remains direct.

The dialog submits only supported settings represented by fields in the current
form. Saving conditionally updates those predicates while preserving omitted
settings, multiple values, unknown RDF and other subjects. All common settings
retain their existing profile-linked storage and behavior.

## Scope and provenance

This records an already-existing candidate recovered from uncommitted work on
main, now isolated in CYC-20261107-QG24H-33. Source and reconciliation scope are
retained in SRC-20261107-QG24H-35. The maintainer recalls earlier planning, whose
original exchange is unavailable here; no exact original design dependency or
prior acceptance is fabricated. Current implementation details are evidenced by
the source and its tests, rather than an asserted historical design chain.

Included: per-app HTML sections, shared partial writes, build-time composition,
RDF-preservation tests, browser checks and related documentation.
Excluded: Rollup/shared bundles, named workspaces, automatic sync, moldability
and the IDE. No shared library source or persistence format is changed.
