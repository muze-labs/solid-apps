# Suite-wide moldable feature composition

Cycle CYC-20261107-QG24H-37. Implements the prospective design
DES-20261107-QG24H-39 following SRC-20261107-QG24H-38. Changes are uncommitted;
exact causal Git references are deliberately not invented.

## Integrated changes

All four app entry points now compose named SimplyFlow datasets and explicit
APIs/runtime state. App-owned actions/model policy use the provided app context
rather than inaccessible module-local state. Global app handles and the existing
diagnostic handles expose their definitions and service state.

- Contacts: list/search/selection, editing and session/state lifecycle. Its
  model retains active filtering when source projections refresh.
- Files: navigation/list, native download commands, editing and resource picker.
  Model options control selection UI; native file access is behind its explicit
  data API using SolidAdapter and the configured Metro client. Partial-upload,
  conditional-write and tombstone behavior remain preserved.
- Launcher: workspace controls, resource selection, shortcut actions and lifecycle.
  Shortcut filtering is model-owned; broker routing and checkpoint authority
  remain behind their existing APIs.
- Profile: resource/local-contact actions and restoration; the shared editor is
  registered in the owning app rather than competing nested bindings.
- Shared: named account/session/lifecycle/appearance and Preferences datasets.
  Shared profile detail/editing datasets use namespaced view/draft state and
  app-specific persistence callbacks. Component initialization is explicitly
  wired through app actions, matching the established reference approach.

jaqt is declared directly where used. Models express object queries through
jaqt in effects; native source data remains authoritative. App-owned provider/
workspace queries and profile field projections use jaqt where it simplifies
existing pipelines. Scalar operations and graph-specific algorithms are not
mechanically rewritten into a query framework.

## Sources, templates and composition

scripts/templates.mjs composes authored view sources at build time and supplies
runtime HTML/CSS entries from those same files. Named views use SimplyFlow's own
field/template rendering, not manual content DOM or an alternate renderer.
The existing bundler captures each named behavior entry's readable source and
origin before minification. Native SimplyFlow merges component defaults and
app-level overrides. A narrow data-layer descriptor retains definitions/origins
and hooks feature cleanup into app destruction; it does not implement another
merge/renderer. Bundle ownership, N3 exclusion and both complete gzip budgets
remain enforced.

App-owned Files data access and Launcher launch/picker modules also retain
their complete readable module source and import dependencies, so the explicit
API boundary does not hide suite-owned policy in minified module closures.

The source metadata and app contexts are developer-facing only. No IDE UI,
user-edit storage, preview isolation or new persistence schema is implemented.
The installed library's live override-deletion/reapplication limitations remain
retained evidence. This supplies the app-authoring pattern without claiming all
future IDE runtime facilities exist.

## Verification relevance

Existing application/browser/native RDF contracts exercise the migrated suite.
Focused tests cover filter/source refresh, picker visibility, DOM-free draft
recovery, unchanged RDF and partial-upload failure. Browser checks reconstruct
production source and reuse the actual migrated Contacts list with explicit
fixture APIs and a template override. This verifies the new integration, not a
separate approval gate for the established reference architecture.

The isolated picker fixture now bundles workspace-broker.mjs because it imports
jaqt. Serving that module raw caused a browser bare-import resolution failure;
using the fixture's existing Rollup mechanism fixes the real dependency setup.
No readiness timeout is increased to hide that failure.

Human evaluation and acceptance remain pending. No commit, merge or publication.


## Evaluation correction: native structured contact values

FBK42 identifies a shared-reader defect: nested vcard:value/hasValue NamedNodes
were stringified as objects and unresolved email resource references were shown
as addresses. The reader now projects recognized scalar/IRI leaves, preserving
multiple values, and bounds traversal through cyclic RDF. Unresolved contact
nodes do not contribute email/phone text and remain protected from structured
flattening during edits. All source statements remain native and authoritative;
no reference cleanup, fetching of linked documents or structured-write feature
is added. EVD43 supplements the preceding refactor verification.


## Organization refinement

FBK44 moves each named feature into its own src/components/<feature>.mjs module.
The seven features.mjs files become re-export indexes. Existing component names,
contexts and imports through those indexes remain usable. Retained-source capture
follows the named exports to their defining modules; EVD45 checks real component
origins and runtime reconstruction alongside the suite's existing checks.


## Explicit text imports and template compilation

FBK46 replaces ?source with import attributes for HTML, CSS and retained module
source strings. Plain text loads no longer transform markup. Root wrappers live
in feature HTML; composed account/Preferences imports explicitly use ?template.
The existing Rollup source plugin and Node loader implement the same contract.
Rollup's pre-resolution import map conflates text/executable imports of the same
specifier. The plugin changes only the parsed import identity for text modules,
retaining authored code and identity source maps; normal modules stay separate.
A contract test verifies raw includes remain literal, explicit composition
expands app markup, and a module read as text can also execute independently in
both Node and the emitted browser bundle. No warning suppression is added.
EVD47 records final checks and size budgets.
