# UI and embedded-capability direction

The maintainer selects the MVP UI work and asks for a top-right dropdown closer
to poef/solid-apps, clear menu highlighting, own-profile access from the account
name, consistent dialogs with optional title/close/always-visible footer actions,
and shared list/details design components. Reuse or extend the-ds and extract
shared design elements into the existing suite library. Prefix globally visible
names to avoid collisions when importing components into another app. Code must
remain clear to people without professional programming experience.

After discussing a shared in-app editor, the maintainer proposes reusing the
capability system and an iframe dialog. Profile editing becomes a capability.
They agree to the concrete proposal: shared dialog presentation, provider-owned
editing and save, existing routing/cancellation, tab fallback, and reuse for the
file picker. Their confirmation is: "Agreed, lets see if we can make it work."
This supersedes the earlier own-profile tab preference and embedding deferral
for the scoped cycle. No general registry or new capability vocabulary framework
is authorized.
