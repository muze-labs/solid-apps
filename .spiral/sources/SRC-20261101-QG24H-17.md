# Native Turtle persistence: JSON strings are forbidden

Direct maintainer instruction, 2026-11-01:

> Make a note: never under any circumstance write a string with json inside a turtle file. If you cannot find a way around it, explain the issue and we'll resolve it together. For solid apps turtle is the native format.

This is a mandatory project constraint, not a preference and not permission to
invent an exception for rdf:JSON, local caches, baselines, fixtures or migrations.
Persistent structures must be represented using native RDF terms and statements.
If representation is unclear, explain the actual obstacle and work it out with
the maintainer before writing. Do not evade the native-format requirement by
moving application persistence to JSON files.

Inspection finds current noncompliance in workspace-state.mjs: setJSON writes
both the Pod snapshot and the local cache as JSON literals, including a serialized
baseline. The managed-workspace design and tests also describe/use that encoding.
There is a straightforward native RDF direction for workspaces, app instances,
resource links and individual UI/draft fields. This note does not claim an
implementation or migration has happened. Existing data must not be destroyed.
The instruction supersedes the JSON-literal design; its design and implementation
are flagged as noncompliant pending native RDF correction. The cycle remains Active.
