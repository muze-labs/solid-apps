# Ignore unknown predicates and discard the retired snapshot on explicit save

The maintainer reports that “choose a fresh native workspace” offers no clear
route and clarifies their expectation: silently ignore predicates the app does
not support or understand, as the linked-data default. Preserve those statements
when writing. Inspection identifies a blanket RDF JSON rejection in StateGraph
before workspace properties can be interpreted, plus an explicit rejection of
the retired apps:snapshot predicate. Both prevent ordinary loading here.

The no-JSON-in-Turtle write rule still applies. Asked whether saving may discard
only the retired apps:snapshot JSON value while preserving all other unknown RDF,
the maintainer chooses: “Discard the retired snapshot”. This authorizes removing
that predicate from the current workspace root during an explicit native save,
without decoding/importing its value. It does not authorize deleting arbitrary
unknown properties, dropping snapshots on other subjects, writing new main-state
JSON, migrating old app state or merging this cycle.

Read valid RDF without a datatype allowlist. Interpret only supported workspace
properties; validate known fields when used and retain unknown triples/identity.
Clone the raw source without serializing forbidden content. Prepare a clean native
draft, but leave the actual source unchanged until an explicit conditional save
is acknowledged. Background close must not perform that one-time discard.
Unrelated RDF JSON remains intact in memory and causes a precise write refusal
under the existing rule, rather than being silently deleted or copied forward.
