# Roadmap additions before the next cycle

The maintainer requests recording the following unordered issues in the roadmap,
not implementing them or selecting another cycle:

- Many 401 responses are visible. Consider Metro force authorization when signed
  in, at least for the current storage Pod; learning domains that return 401 and
  subsequently forcing authorization there may be the best option.
- The profile name should open the profile editor in a new window, reusing an
  already-open editor where possible.
- Preferences should distinguish common settings shared across apps from settings
  specific to the current app. Storage belongs to the app-specific options.
- Include the original dark/light and font-size options in the common settings.
- Launcher should support choosing between multiple workspaces. Creating and
  switching workspaces belong in its app-specific preferences. Workspace closure
  should be tied to logout.
- The dashboard should be sparse, showing user-added shortcuts like a phone home
  screen. The only default links should open Files at each storage location
  listed in the user's profile.
- A suggested (+) affordance opens an add-shortcut dialog.
- Start the app store as a folder of Turtle files: an index with name, icon and
  manifest link, and one manifest per available app.
- Include existing stable Solid apps even when they do not implement this suite's
  ecosystem protocol.

Clarifications, asked one at a time:

1. Closing Launcher should still close its managed apps; logout should also close
   the workspace.
2. Only Launcher logout closes the whole workspace. Logout in another managed app
   does not close the whole workspace.
3. When no Profile editor is open, clicking the account name should “Follow the
   tabs/windows preference”. Reuse an existing editor when available. This
   clarifies the original “new window” wording.

Inspection finds Theme (System/Light/Dark) and Text size already implemented in
shared Preferences, alongside all apps' storage fields in every app. The desired
common/app-specific split is new; these existing controls should be retained,
not duplicated. Current Solid sessions force authorization for writes only.
Named workspaces and decentralized catalogs are already planned, but the new UI
placement and concrete first catalog format refine that direction. Interpret
“dashboard” as Launcher home, since no separate dashboard application is defined.
The authentication approaches remain candidates: the maintainer phrases them as
“I think” and “might”, not a settled token/routing policy. Third-party app selection
and current stability verification belong to a future implementation cycle.
