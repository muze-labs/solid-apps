## Investigation and preflight

EVD57 from CYC49 establishes the live failure: same-origin tabs and embedded
Profile share expired access authorization, no refresh token and cached identity.
Reconnecting fixes it. Firefox fixtures demonstrate that installed Metro already
reuses valid cached tokens and silently refreshes when a refresh token exists.

The installed and latest published versions checked during this investigation
are metro-oidc 0.9.4, metro-oauth2 0.9.3 and jsfs-solid 0.1.1. OIDC defaults to
openid/webid scopes; suite connectSession does not request offline_access.
OAuth refresh failure currently throws an error containing response text without
a structured OAuth error code or automatic fresh-authorization fallback.
Existing account reconnect reloads app data and is unsuitable for preserving
an in-progress draft. A cached ID token is currently used as a popup-reservation
shortcut, although it does not establish usable resource authorization.

Proposed boundary: keep tokens, refresh, OIDC validation and HTTP in Metro;
add suite-owned recovery presentation and preserve drafts/conditional writes.
Distinguish expired authorization from connection errors and access denial.
Do not blindly replay a complete operation that may have partly written data.
Request offline authorization with appropriate consent where supported; do not
promise that every provider issues refresh tokens. Hidden-iframe prompt=none
remains an optional later fallback rather than a prerequisite for this cycle.

The maintainer confirms "Yes, use refresh-first recovery" at the intent/reality
gate. DES69/IMP70/EVD71 record the design, implementation and verification.
No upstream library modification, publication, commit, merge or push is authorized
by that implementation confirmation. Required evaluation includes refresh and recovery,
failure/cancellation and draft preservation, npm run check and browser suites.
