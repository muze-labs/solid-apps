# One-click Files activation and startup verification

Date: 2026-11-01. Implementation `2167765`; source FBK20.

The maintainer's manual test confirms that the picker already renders in Files
when switching there manually. An isolated predecessor browser probe independently
showed delivery while Launcher remained focused, and result return while Files
remained focused. This identifies activation, not a missing selection UI, as the
reported existing-provider gap. The maintainer explicitly keeps activation and
bounded built-in startup in the same cycle.

Verification on the correction:

- `npm run test:picker` passes sixteen direct transport/policy cases and the
  isolated Chrome browser proof. It invokes no WorkspaceState, Pod writes or
  JSON-in-Turtle persistence. Static protocol fixtures import the real broker,
  managed-app client and bundled Launcher picker policy.
- Unit contracts cover synchronous opening before startup awaits, saved/live
  instance reuse, denied grants, ambiguity, cancellation, popup blocking, restore
  errors, readiness deadlines and permission rechecking before invocation. An
  explicitly targeted request cannot fall back to another provider. Transport
  checks also preserve checkpoint, isolation and cancellation behavior.
- One browser click with no pre-opened Files creates the cross-origin provider,
  waits for its verified ready connection and activates its tab. Selection returns
  the full fixture resource URL with fragment. After a 6.1-second idle interval,
  another click reuses and activates the same Files tab rather than duplicating
  it. Provider cancellation returns the cancelled result without closing Files.
- Returning focus to Launcher is advisory. The client now requests it from the
  selection/cancellation action, but Chrome 131 headless kept Files visible in
  both observed cases. The test records those observations separately instead
  of claiming a guaranteed return. Files explicitly tells the user to switch
  back when needed. The platform permits focus refusal:
  https://developer.mozilla.org/en-US/docs/Web/API/Window/focus
- Initial test assertions expecting guaranteed return focus failed; the browser
  observation narrowed that claim to requests plus fallback, as the design
  already allows. A headed diagnostic on this display did not reliably deliver
  fixture input, so no graphical-browser or Firefox certification is claimed.
- `npm run build` passes. Full JavaScript graphs plus auth callback: Launcher
  193329, Contacts 185487, Files 168861, Profile 185338 gzip bytes, below 200000.
- Spiral snapshot validation, new-reference ancestor/artifact checks and
  whitespace checks pass.

The full `npm run check` and `npm run test:browser` commands were deliberately
not rerun: their current persistence fixtures exercise the forbidden main-state
JSON-in-Turtle encoding retained as DEF18. The isolated suite covers this
activation/startup correction without making an exception to that rule. No
persistence encoding, migration, provider registry or new dependency is added.

CYC2 remains Active for renewed human evaluation; ACC19 retains acceptance of
its earlier snapshot. DEF18 stays Open. The local build is updated; reload
Launcher and existing Files tabs to load the new startup/client behavior.
No merge or publication was performed, and no actual user Pod was accessed.
