# Checkpoint deadline and stale-channel recovery verification

Date: 2026-11-01. Runtime implementation `d793986`, following FBK13.

The timeout comes from the app checkpoint phase before a workspace Pod write.
A disposable probe on the predecessor showed a healthy three-second response
failing under the 2500 ms deadline. The report did not identify which live app
failed, so this evidence does not assert that this probe was the user's exact
failure. Pagehide closes a client port and the predecessor ignores its same-
generation resume; code establishes another plausible cause of repeated timeouts.

Checks:

- `npm run check` passes six test files and the build. There are nine direct
  capability/transport cases, including a real three-second healthy response,
  restoration versus readiness, named restoration failure, timeout with prior
  state/window retention, healthy sibling checkpoint preservation, successful
  checkpoint after reconnect, and protection against replay for older clients.
- `npm run test:browser` passes existing workflows plus the extended managed
  workspace proof. Its controlled three-second app state capture saves normally.
  An intentionally nonresponding app and reduced test deadline produce a named
  failure, no Pod PUT and no closed app. Restoring the handler/reconnecting then
  saves normally.
- Chrome dispatches pagehide/pageshow with persisted=true to exercise the retained
  page handlers. The same-generation connection recovers, publishes a live-only
  state value, and invokes the wrapped restoration callback zero times. This
  demonstrates handler/protocol behavior; it is not a complete browser BFCache,
  discarded-tab or mobile-suspension certification.
- The final focused managed-browser run also passes with success paths waiting
  for readiness rather than registration. Its existing conflict, reload,
  conditional save, restoration and ordinary close-time fixture proofs pass.
- Per-app gzip JavaScript including auth callback: Launcher 192214, Contacts
  185469, Files 168812, Profile 185320 bytes, all under 200000.
- Spiral snapshot validation, ancestor/artifact reference checks and whitespace
  checks pass. No merge or publication was performed.

One earlier full-suite run missed Profile launch initialization; a repeat full
run passed without changing that startup behavior. Failure diagnostics now retain
its URL/launch context if repeated. No cause for that intermittent observation
was established, and this is not claimed as a repaired startup defect.

These remain isolated browser/Pod fixtures. No real user Pod was changed and
real-provider authentication during shutdown is not proven. The local static
build is updated, but already-open tabs retain older JavaScript and may require
reload. Older timed-out clients are asked to reload rather than automatically
replaying cached state over possible live drafts. Human acceptance is pending;
the active cycle remains open for the maintainer's next local evaluation.
