## Reference and library investigation

Reference sources and commit baselines are recorded in FBK64. Public repos:
https://github.com/SimplyEdit/simplyedit-backend and
https://github.com/poef/solid-apps . Existing suite fullscreen rules already use
max-width:719px with a 100dvh viewport. Preserve them rather than inventing a new
breakpoint or claiming fullscreen is newly implemented.

Installed the-ds 0.2.7 provides native dialog styles but no shared entry/exit
lifecycle. CSS-only close transitions depend on deferred top-layer removal;
Firefox 157.0.1 reports CSS.supports('overlay','auto') false. Direct disposable
probe /tmp/cycle49-dialog-animation-probe.mjs and .log confirms native Web
Animations supports ::backdrop and intermediate backdrop color in Firefox.
References: https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog#animating_dialogs
and https://raw.githubusercontent.com/mdn/browser-compat-data/main/css/properties/overlay.json .

Thus a narrow shared native-lifecycle bridge animates the dialog and its native
backdrop over 300ms. It keeps native modality until the exit finishes, then calls
close for focus restoration. Reduced motion skips animation. Closing during
entry starts from current computed opacity/transform; repeated close requests
share one pending close. Animations are cancelled/cleaned up afterward.

All suite opening/closing commands use the shared actions. Simple dialogs opt
into the shared Escape behavior; capability Escape remains owned by its existing
save/draft close guard. Capability release keeps the frame visible through exit,
then clears it. No content renderer, fake backdrop, global event infrastructure,
native method patch or new dependency is added.
