## Guardrails and limits

This repairs shared settings behavior without expanding any app's task. Open
form edits survive failed requests, conflicts and existing sign-in recovery;
the existing full session browser suite checks conditional saves and auth/cancel
preservation. No reload-persistent Preferences drafts, offline app shell or
automatic sync is implemented. Reload can still lose unsaved Preferences edits.
If a provider never supplies strong GET validators, conditional saving cannot be
made safe by this client: retain choices, explain the provider limitation and
offer retry/review rather than silently overwrite. Explicit Review shows current
Pod settings and keeps user changes in memory for explicit restoration; a
successful Save or explicit reset clears them. No automatic merge/save is claimed.
Native controls, keyboard tests, accessibility-tree inspection and screenshots
are bounded evidence; no real screen-reader user study or live-provider test is
claimed. Wider forms visual design remains separate roadmap work.
