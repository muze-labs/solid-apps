## Corrections and limits retained

Initial runtime attempts exposed premature port delivery at frame load, nested
view placement before initialization, duplicate profile loading that could reset
an edit, temporary providers being reopened during restoration, and cleanup
handling of synchronous versus asynchronous broker interfaces. Those integration
gaps were corrected. The managed fixture originally expected picker UI in the
already-open Files tab; it now checks the intended embedded flow and preservation
of that independent instance. The separate top-level protocol coverage remains.

One navigation run reported `Failed to fetch` while restoring the account before
Launcher initialization. Later full runs pass, but that result does not establish
its cause; prior intermittent readiness evidence also remains retained. No global
readiness timeout was increased to conceal it. The explicit 20-second framing
startup deadline is separately exercised by the refusal/fallback scenario.

Fixtures do not verify live Solid OIDC, third-party session/storage behavior,
arbitrary providers' framing policies or guaranteed browser-close delivery. The
protocol sends no OAuth credentials; same-origin presentation is not a credential
sandbox. Task drafts remain in the live provider rather than a new persistent
workspace format. Normal checkpoints refuse them; forced browser closure is still
a bounded best-effort boundary. Wider account propagation, persistent provider
registry, recipient selection, stage-two work and the live IDE remain deferred.
