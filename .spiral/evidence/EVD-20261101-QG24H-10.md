# Managed workspace and Pod checkpoint verification

Date: 2026-11-01. Revised implementation: `101a053`.
This replaces the server-proof evidence for the revised requirement; it does
not claim Launcher-independent sessions in the new architecture.

## Observed outcome

`npm run check` passes six test files and the four-app build.
`npm run test:browser` passes the existing app workflows and the new managed
workspace fixture. The real browser opens Launcher on 127.0.0.1 and Files on
localhost, distinct origins/sites, with ordinary opener relationships.

The managed fixture verifies selection and cancellation, per-instance grants,
no continuous Pod PUT, unknown RDF preservation, no exported reconnect keys,
Launcher reload without duplicate apps, child reload with restored folder,
and two Files instances retaining different folders. Explicit Save & close
waits for a conditional authenticated fixture PUT and closes children. A fresh
Chrome profile loads the app set from the Pod and restores it. Restoring multiple
apps uses popup permission; the ordinary suite also checks tab/window preference
with normal popup policy.

Conflict (412), forbidden (403), and offline/dropped-socket writes leave apps
open and local state dirty. Unit contracts cover call cancellation, timeout,
disconnect, source/origin binding, routing denial, wrong-account saving,
unsupported snapshot values, conditional headers and native RDF preservation.
Draft restoration is verified through the shared Contacts profile editor;
restoring a draft does not write its field text to the native graph.

After both restored children joined, a normal DevTools Page.close on Launcher
triggered a prepared write. The fixture delayed its response by 200 ms. It
received the expected conditional header, test bearer credential and latest
state; both participating children closed. Retained experiment result:

```json
{
  "browser": "Chrome/131.0.6778.204",
  "explicitPodSave": true,
  "freshBrowserPodRestore": true,
  "nativeCloseWriteReceived": true,
  "nativeCloseAuthorized": true,
  "fixtureAuthentication": true,
  "realSolidOidcNotTested": true
}
```

The live path uses Metro's keepalive request option and existing session
noninteractive authentication. Test-only middleware supplies the fixture bearer
credential. This does not establish real Solid OIDC/DPoP renewal during shutdown,
all browsers, mobile lifecycle behavior or crash recovery. Browser-X delivery
remains best effort and never clears local pending state as if acknowledged.
Manual validation with the maintainer's actual Pod remains outstanding.

## UI, size and process

The 390px Files picker screenshot was visually inspected and its no-horizontal-
overflow assertion passes. Review captures/result JSON are temporary files in
`/tmp/solid-apps-review/`. Final gzip totals including import graph and auth
callback, gzip level 6: Launcher 190267, Contacts 185238, Files 168578,
Profile 185088 bytes. All remain below the 200000-byte budget.

Verification exposed a child-closure defect: reading window.opener dynamically
can lose the reference after closure. The client captures the opener and checks
it while connected or reconnecting. The closure proof waits for both apps to
join, making its lifecycle precondition explicit. Browser assertions also now
wait for navigation/load and rendered save completion rather than racing them.

Spiral snapshot validation and whitespace checks pass. New causal references
were checked for full hashes, ancestor reachability and artifact paths before
committing. This is bounded validation of the introduced references, not a claim
that every historical artifact version was audited. No agent merge or publication
was performed. Human acceptance remains pending and the cycle remains Active.
