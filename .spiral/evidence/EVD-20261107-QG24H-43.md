## Current results

- Before the correction, synthetic fixtures produce `[object Object]` for
  blank-node and named-node email wrappers with NamedNode values. A plain literal
  vcard:value works; a direct mailto node works. This locates the gap in the
  shared native-RDF reader rather than in SimplyFlow rendering.
- The public-document Metro probe matches the maintainer's two distinct shapes:
  a described node with a mailto value and a dangling reference without value
  statements. The corrected probe reports exactly one projected address, no
  object placeholder, no resource reference in the text and an unchanged graph.
  No user address was printed or saved and no Pod write was attempted.
- `npm run check` passes all 12 test files and both bundle variants.
- A direct run of `test/data.test.mjs` passes all 14 named tests, including the
  structured/multiple-value, unresolved/cyclic and URI-scheme-casing regressions.
- Added native graph tests cover blank/named wrappers, vcard:value and hasValue,
  multiple values per wrapper, mailto/tel values, unresolved references and
  cycles. Unsupported structured edits fail before any partial mutation. An
  unrelated name edit preserves all remaining RDF isomorphically, including
  anonymous-node structure, metadata and dangling links.
- The own-profile Chrome fixture has the same named-wrapper/dangling-link shape.
  General app browser checks pass: viewer/editor show `owner@example.org`, not
  object strings or the unresolved reference; saving the name retains both the
  reference and wrapper metadata.
- `npm run test:browser` passes all three Chrome suites on the final build:
  general apps, managed workspace and isolated cross-origin picker.
- The Profile desktop fixture screenshot was inspected after saving its name;
  it shows the address value without the object placeholder or dangling node URL.
- Spiral snapshot validation passes: 150 Turtle files / 1778 triples.
  `git diff --check` passes and the actual branch matches the Active cycle.
