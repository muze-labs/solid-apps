# Unknown-predicate reads and same-target retired snapshot cleanup

Date: 2026-11-01. Implementation `1f8c450`; authorization SRC27.

The maintainer reports the fresh-workspace message and explains the expected
linked-data default: ignore unknown predicates when reading and preserve them
when writing. They explicitly choose discarding the retired snapshot after the
conflict with the no-JSON-in-Turtle write rule is explained. This supersedes the
fresh-URL workaround in EVD26; that earlier verification stays historical.

The parser now accepts valid RDF without rejecting an entire document based on
an unknown datatype. The workspace projection ignores apps:snapshot. Raw source
cloning avoids serializing forbidden content before cleanup. The Pod storage
boundary removes only apps:snapshot on the current root from its prepared draft;
the generic native writer preserves unknown properties. The actual Pod changes
only on explicit conditional Save/Save & close. A prepared discard cannot be
sent by the background-close path. Other unknown RDF is preserved; unrelated
RDF JSON gets a precise write refusal and is not silently dropped or re-emitted.
