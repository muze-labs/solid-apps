# Workspace conflict recovery verification

Date: 2026-11-01. Implementation `bbc2da5`; feedback FBK11.

The maintainer recovered the exact error after the initial failure report:
`workspace-state: Pod conflict; local state is retained.` Code and fixture
reproduction show why reload alone cannot recover: pending local state and a
new remote version reproduce the refusal, without a resolution control. This
identifies the missing recovery mechanism, but does not establish whether the
maintainer's remote version came from another session or a close-time write.

Verification:

- `npm run check` passes six test files and the four-app build. The state file
  has seven direct contract cases, including conflict persistence across reload,
  review-before-resolution, newer-ETag refusal after review, unknown RDF/key
  preservation, using Pod state without PUT and retry after missing ETag.
- `npm run test:browser` passes all existing app workflows and the extended
  managed-workspace proof. After the final state-channel guard, the focused
  `node test/managed-browser.mjs` also passes against the rebuilt snapshot.
- Chrome reproduces an actual ETag conflict, reloads it, exposes Review Pod
  conflict and checks that another ordinary Save & close does not enter the
  interactive authentication operation. Offline/403 errors are shown beside
  the button, and the last error is still visible after reload.
- Review fetches and displays the changed Pod snapshot. A second Pod change
  after review causes another 412; the remote state remains intact. Reviewing
  again and keeping local succeeds with a conditional write and retains unknown
  native RDF. Using the Pod version updates the resource field, replaces and
  reconnects the app set, and issues no PUT of app data. Busy controls settle
  and re-enable; Save & close then works again.
- The broker contract rejects state messages while the session is closing or
  being replaced, preserving the selected snapshot from stale app messages.
- The 390px conflict view was captured and visually inspected; no horizontal
  overflow was observed/asserted. Capture:
  `/tmp/solid-apps-review/workspace-conflict-mobile.png` (temporary review file).
- Full-graph gzip totals including auth callback: Launcher 191445, Contacts
  185238, Files 168578, Profile 185088 bytes, all below 200000.
- Spiral snapshot validation, new-reference ancestor/artifact checks, and
  whitespace checks pass. This is bounded verification, not a historical audit.

The browser test uses an isolated fixture with test bearer authentication, not
the maintainer's actual Pod or real OIDC renewal. Ordinary close-time persistence
remains best effort; it was received again in Chrome 131. This change deliberately
does not silently pick a side in the maintainer's conflict. The running local
static build is updated; the maintainer can reload and choose a version.
Human evaluation remains pending. No merge or publication was performed.
