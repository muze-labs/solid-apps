# Select a Pod resource through another app

Launcher must be able to request a resource selection from an already-open
Files app on another origin and receive the full URL into its resource input.
Files retains its standalone browsing behavior and its own Solid session.
The request grants no Pod access and does not authorize a write or download.

The provider shows who requested the selection and offers explicit Select and
Cancel controls. Cancellation preserves the caller's existing resource input.
Disconnect, timeout, denied access, invalid credentials and unauthorized routes
must fail visibly without silently selecting another provider or hanging.
Routing is private to authenticated, explicitly allowed app/workspace relations.

Keep the service self-hostable and the client independent of the renderer.
Use SimplyFlow for suite UI, preserve existing workflows and unknown RDF in
preferences. Broker URI uses the existing linked preferences; connection keys
are not stored there. Measure required JavaScript below 200 KB gzip per app
and review the interaction at mobile width.

Unknowns settled by design: initial provisioning and transport, exact capability
URI and input/result representation. No registry, discovery, cold launch,
collaboration, access delegation or new application is required.
