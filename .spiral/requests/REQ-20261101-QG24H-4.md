# Browser-local managed workspace and resource selection

Launcher owns managed app instances and brokers their capability requests inside
the browser. Replace the server relay and provisioned connection keys. Keep
ordinary opener relationships, verify origins/window identity, and scope every
request/result to its participating instances. Retain explicit selection,
cancellation, failure handling and native RDF preservation.

Save each instance's launch context and serializable restoration state locally
as apps update it. Reopening Launcher restores the saved desired app set, with
visible recovery when popup policy blocks automatic restoration. Managed apps
close when Launcher closes; cooperative detection must not depend solely on an
unload callback. Standalone apps remain independently usable.

Test storing the workspace state in the connected user's Solid Pod at closure,
without continuous Pod writes. An explicit Save & close waits for a conditional
Pod acknowledgement before closing apps. Normal tab closure attempts a bounded
keepalive write from prepared state without prompting for login; it cannot be
reported as an acknowledged save. Keep recoverable local state after offline,
authentication, conflict or lifecycle failure. Do not overwrite another account's
workspace or unknown RDF, and do not store credentials in restoration state.

Verify cross-origin picker use, per-instance isolation, reload/reconnect,
close/restore and Pod save/reload with fixture data. Preserve existing workflows,
SimplyFlow rendering, mobile usability and the 200 KB gzip JavaScript budget.
Multiple named workspaces, catalogs, full PWA/offline data and collaboration
remain future work. The earlier independence-from-Launcher acceptance criterion
is superseded for managed sessions.
