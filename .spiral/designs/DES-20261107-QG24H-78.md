# Acknowledged saves and safe Preferences recovery

The maintainer confirms reliable Preferences saves and recovery after the
understanding/gap checkpoint. The disposable 205/no-ETag probe reproduces that
exact failure. Keep success acknowledgement distinct from obtaining a next-write
validator: never report a successful write as a failed save because a later read
fails, and never repeat an acknowledged write merely to obtain its ETag.

Retain a resource's native source in the existing document helper. On a missing
validator, read the current resource through Metro and compare the whole native
RDF baseline with the existing bounded sameGraph helper, using the actual base
URL. Accept reordered Turtle/blank-node renaming, not a changed graph. Require
a usable strong ETag and keep If-Match/If-None-Match; concurrent changes still
fail conditionally. Read errors, permission failures, missing validators,
conflicts and unconfirmed write outcomes have distinct recoverable status.

Inspecting public OLDM write/patch and oldm-turtle APIs found no graph equality
API, and a probe shows object writing duplicates a shared unknown blank node.
The patch writer also starts with that object serialization. For Preferences,
reuse the suite's existing StateGraph and oldm-turtle native terms to modify
only explicitly supplied settings, preserving unknown triples/subjects/shared
and cyclic blank nodes. Keep OLDM for the read projection and existing field
validation. Do not build another parser, equality algorithm, HTTP client or
workspace snapshot. Other profile/document editing is not rewritten here.

On failure retain the open form. Retry uses the entered choices. Review Pod
settings fetches before replacing the view, keeps only user-modified fields as
an in-memory recoverable draft, and displays current Pod values. Restore my
changes reapplies those fields over that reviewed baseline, retaining other
remote changes; the next Save is still conditional. No automatic overwrite or
silent discard occurs. A failed review leaves the form and baseline untouched.
New commands/data use the requested swb_ / swb- convention. Remove the bare URL.

This remains explicit save/recovery: no automatic sync, offline application shell
or reload-persistent Preferences draft cache is introduced. That existing gap
must remain visible in evaluation; this fix preserves edits during the open
interaction and avoids forcing reload to recover. Evaluate phone/desktop and
keyboard/status/focus behavior and distinguish automated checks from actual
assistive-technology review. Existing size ceiling remains enforced.

Applicable culture: Muze engineering and library stewardship cover shared
packages and favor small readable direct API composition. Mandatory native RDF,
conditional writes and confirmed guardrails govern this design. Adopted
WPF-HUMAN-001 composition/evidence concerns require whole-graph preservation,
explicit reviewed recovery and no claim that fixtures prove live usability.


Evaluation refinement within the confirmed recovery goal: keep blocking recovery
status beside the fixed footer actions, dismiss obsolete success toasts when a
new operation starts, and focus a newly available action only after SimplyFlow
has actually enabled/revealed it. Its installed 50ms throttling disproves the
initial animation-frame assumption; a native attribute observer supplies only
the missing focus-completion bridge. Rendering stays entirely in SimplyFlow.
