# Moldable suite composition

Use named SimplyFlow component datasets around existing features, following the
reference rather than introducing a new component framework. Commands use the
provided app context, read DOM/native input and invoke named actions. Actions
use explicit app data APIs/libraries and app-owned runtime state; edits must not
depend on hidden module closures. Keep native RDF operations behind existing
Solid APIs. The shared editor remains independent of persistence policy.

Model source is a UI projection. SimplyFlow model effects own transformations;
jaqt may express the query in those effects. Commands change options; templates
bind the model view. Source refresh must preserve active options and selected
IDs/drafts. Document and clean up model effects with the feature lifecycle.

Expose authored component definitions and app overrides through the running app,
with origin/readable source and documented dependencies. Generate runtime HTML
and CSS entries from the same files used for build-time composition; preserve
useful View Source. Retain authored function source before minification so
replacements use the documented app context, not bundler-local identifiers.
SimplyFlow continues to merge defaults and app-level overrides. Source retention
must not grow a competing merge/renderer. Initialization remains explicit at app
level where the installed library does not invoke component start hooks.

Keep broker/persistence mechanisms and external libraries callable behind their
existing APIs; expose the suite-owned policy/feature wiring as entries. Preserve
current public diagnostic handles while adding app/definition access. Verify the
whole migrated suite and actual integration gaps; no separate pilot gate.

requested; no placeholder hashes or historical approvals are invented.
