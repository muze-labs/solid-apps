# Resolve named actions when an existing caller invokes them

The confirmed cycle addresses action dispatch, not a new component runtime.
Inspection of simplyflow-app 0.10.3 shows a mutable public actions proxy: reading
an action binds its current function; assigning a replacement changes later
lookups. Component merge builds the effective action table separately from raw
component entries. Original source/definitions remain exposed by exposeDefinition.
There is no published runtime personal-layer manager in this installed API;
exposeDefinition intentionally supplies source metadata only.

Use direct public action lookup at invocation at the suite's long-lived edges:
widget methods, shell host methods, broker/managed callbacks, timers and stored
native event handlers. Preserve arguments, result/promise and SimplyFlow's this
context/error handling. Store one forwarding listener for registration/removal
so cleanup removes the actual listener. Do not wrap immediate calls just because
they receive a function, or treat already-started async work as a fresh invocation.
Do not add a generic proxy, override engine, dispatcher framework or dependency.
The concrete gap is retrieval-time binding of captured functions; these limited
forwarders connect existing callers to the supported current-action API.

Tests apply a replacement to the runtime action table and restore its previously
effective definition through that same public API, in an existing browser app.
Keep component originals inspectable and distinguish that effective assignment
from changing source metadata. Future IDE personal-layer management will use
SimplyFlow composition and must coordinate runtime updates; it is not implemented
by this cycle. Preserve app-owned original overrides, not merely component defaults.

Reconcile the design's personal-layer and current-action expectations, document
independent future IDE/app histories, marketplace separation and upstream-version
questions, and retain accepted build-time composition/current project guardrails.
No visual rendering, model recomputation notification or event-ownership migration
is added. Native focus/dialog operations remain direct.

Active culture: CUL-MUZE-001 applies suite-wide; CUL-MUZE-LIB-001 applies shared
packages/tooling. Their readable direct composition preferences support limited
bridges over a new runtime. Architecture philosophy and mandatory RDF/authority
rules take precedence. WPF-HUMAN-001 warrants checking composed existing callers,
not claiming source exposure or a green isolated probe proves live replacement.

On removal, restore the raw authored effective definition, including any app-owned
default override, rather than a callable already bound by the proxy. That avoids
re-wrapping SimplyFlow error handlers. Raw definitions remain inspectable in the
existing component/app metadata. No general override-stack API is added.
