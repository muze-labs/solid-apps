# Readable and minified module graphs

## Outcome and current gap

Add minified production bundles while retaining the existing readable output.
The current Rollup build only emits .js files. Keep existing shared-layer,
app-isolation, RDF-backend, source-map and size-budget contracts in both graphs.

## Decisions

Generate readable .js and minified .min.js outputs from the same Rollup input.
Use the published @rollup/plugin-terser package rather than a private minifier.
Rollup generates each graph's import filenames so production chunks only import
other minified chunks. Retain original source content in both sets of maps.
Do not enable property-name mangling. Preserve function/class names for useful
runtime inspection while reducing formatting and local variable names.

Production pages and the auth callback load .min.js. A --readable build option
selects .js references; npm run dev uses it. Both output sets are emitted either
way. Report both app/callback graphs and keep the strict 200000-byte gzip limit
for each variant. Existing apps entries in the size report describe production;
a separate readableApps section exposes readable totals.

## Verification

Extend bundle contracts to both output graphs, checking self-contained imports,
matching public exports, unique module ownership, required source maps and a
smaller total minified payload. Browser tests run production pages against the
minified graph. Verify --readable selection separately and restore production
output afterward. Run npm run check, npm run test:browser, graph and diff checks.

## Scope and references

This is an explicit addition to Active CYC-20261107-QG24H-34. It changes build
outputs and entry references, not content rendering, app data or library APIs.
Keep readable sources available for the future IDE; this does not implement it.
The earlier intermittent managed-workspace failure remains retained.
