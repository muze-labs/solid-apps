# Temporary notifications and profile trigger accessibility

Maintainer requests toasts for temporary messages and no underline/link coloring
on the user name. They suggest a possible dialog-opening icon but explicitly ask
for research, including accessibility, rather than selecting that icon.

Effective gap: shared completion messages use the persistent suite-status;
Preferences success uses its inline form message. The user name is an anchor
styled as a navigation link although ordinary activation opens a dialog.

WAI's button pattern identifies dialog opening as a button action and mentions
ellipsis as a convention, not a required icon. Chosen local implementation: plain
native button, inherited text color, descriptive accessible name containing the
visible name, aria-haspopup=dialog, visible hover/focus treatment, native Space/
Enter activation and dialog focus return. No speculative dialog icon is added.
This intentionally changes the trigger from navigation/modifier-click semantics;
standalone provider navigation remains available in the capability fallback.

Temporary completion feedback uses the-ds toast styling through a shared editable
SimplyFlow component. Nonessential confirmations expire after eight seconds,
pause while hovered/focused and have a labelled dismissal action. Persistent
errors, actionable instructions and operation state remain inline. No auth change.


Follow-up: Contacts still displays Connected to this workspace. Maintainer says
successful connection is default behavior and needs no message; failures must
remain visible. The effective source is ManagedApp.offer's successful handshake
callback, shared by all ordinary managed apps. Remove that success notification
at its source; retain the catch-path error callback and readiness protocol.


Further follow-up: Launcher shows capabilities: Selection cancelled after normal
capability cancellation. Maintainer asks for the same quiet-default treatment.
Use the structured cancelled code in shared command error handling and Launcher
selection; do not match error text or suppress failed/disconnected/denied errors.
Provider-owned Files cancellation also clears its transient request status.
