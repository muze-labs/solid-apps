# Save & close times out collecting app state

The maintainer reports `save&close: capabilities: Request timed out.` after the
conflict recovery correction. Save & close issues MessagePort checkpoints before
its Pod write. The code gives each app 2500 ms and returns a generic timeout
without naming the instance. A disposable probe confirms that a healthy app
returning state after three seconds is refused.

Related lifecycle inspection finds that pagehide closes the child port while
same-generation resume is ignored by Launcher. Such a retained page cannot
recover its connection. The child also waits on network-backed restoration
before answering checkpoints, although registration already appears Connected.
These are evidenced failure modes, not proof of which affected this user.

Continue the current cycle: distinguish restoration from readiness; use a
bounded ten-second checkpoint deadline; identify the failing app; reconnect a
stale private channel without replaying saved state over a live draft. Report
restoration failures and preserve app windows/local state when a fresh checkpoint
is unavailable. Do not silently substitute cached state and close apps. Verify
slow responses, pagehide/resume recovery, draft preservation and save retry.
