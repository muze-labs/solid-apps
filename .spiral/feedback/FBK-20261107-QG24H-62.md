# Stable capability loading presentation

Maintainer says iframe dialogs work but show jumpy loading. They request a
centered loading animation followed by the loaded content, suggesting an explicit
provider message and a fallback when no message arrives.

Investigation: host reveals the frame immediately when setting src. Existing
solid-apps:embedded-ready announces only the transport listener; it does not mean
request-specific content has been bound. The frame viewport must remain sized
while concealed so responsive layout does not start in a zero-size hidden box.

Before implementation, presented this effective gap and proposed a separate
presentation-ready signal, stable loading area, legacy load-event fallback,
five-second grace period for providers promising an explicit signal, reduced
motion, and accessible close/error recovery. Maintainer explicitly confirmed:
"Yes, add provider-controlled readiness with fallback."

This extends presentation only within active CYC49. Readiness is not a capability
result or grant of data authority. Keep frame-window/origin/task binding, Metro
and provider-owned save/draft/auth contracts intact.


Follow-up: maintainer says loading is much better but the reveal is abrupt.
Requests loading fade-out and content fade-in over about 0.3 seconds. Keep the
confirmed readiness/fallback contract; this is a local presentation refinement.
