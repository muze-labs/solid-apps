# Prefer text import attributes for authored sources

The maintainer asks whether HTML supports the import attributes used by the-ds
for CSS. Investigation established the Stage 3 Import Text spelling, with
{ type: 'text' }, and verified installed Rollup support with a disposable probe.
The existing ?source loader additionally composes and wraps HTML. After the
proposal to use text imports and make composition explicit, the maintainer says
"make it so". This confirms the change within Active CYC37, without reopening
its goal or inferring acceptance.

Raw HTML, CSS and module sources should use text import attributes and preserve
the authored bytes. Feature HTML contains its own display:contents root. Only
account/Preferences views needing includes and app-specific expansion use the
explicit ?template build step. Both build and Node test loaders use the same
compiler; SimplyFlow remains the only runtime renderer. Import Text is Stage 3,
not claimed universally implemented. References: TC39 proposal-import-text and
HTML Standard module-type-allowed, checked 2026-11-07. EVD47 retains verification.


## Deferred composition limitation

The maintainer subsequently says the current approach is "good enough for now"
and explicitly requests recording build-time composition as an aspect to revisit
later, possibly using runtime templates and/or SimplyFlow fields. Expanded
runtime templates can be inspected, but their source include relationships and
placeholder expansion cannot be recomposed in the running app without a build.
The suite roadmap and moldable design now retain this limitation and candidate
future mechanisms. This is agreement to defer this specific aspect; it is not
acceptance of the entire Active cycle or authorization to implement runtime
composition now. No product code, tests or build configuration are changed.
