# Profile dialog live feedback

Maintainer confirms the capability dialog works, but reports four defects:
preferences dropdown visible inside it; uneven close-button inset; live profile
error `oauth2mw: authorization response is missing iss, expected
https://solidcommunity.net/`; Edit profile lacks recognizable button styling/icon.
This is correction within the confirmed CYC49 UI goal, not human acceptance.

Effective code confirms account menu remains present on task error, close lives
inside padded header flow, and Edit uses only the neutral button class. Installed
metro-oauth2 0.9.3 treats every nonempty location hash as an OAuth response before
checking for code/error. Task URLs carry ordinary webid/resource launch context.
A deterministic real-middleware test reproduces the reported missing-iss error.
Solidcommunity discovery advertises authorization_response_iss_parameter_supported
true, so issuer validation must remain strict. Popup helper already forwards iss.

Correction: capture validated task launch context and consume its known URL
parameters through the existing launchUrl API before account restoration. Keep
normal standalone launch addressing unchanged. Hide task account menus through
SimplyFlow; retain a direct connection action for sign-in/error recovery. Position
the shared close control at the header corner and add a primary Edit button/icon.
No new auth stack, issuer bypass, external library edits or dependency changes.
