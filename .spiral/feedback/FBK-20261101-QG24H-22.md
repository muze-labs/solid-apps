# Picker return activation and an orphan sign-in tab

The maintainer confirms opening/activating Files now works, but returning to
Launcher on selection does not. Browsing a protected directory opened a white
tab, probably showing the authentication callback message. Asked whether it
said “Completing sign-in…” and the directory loaded, they answer “I think so”.
The exact message/loading result remains uncertain; no credentials were requested.

This continues the already authorized picker correction in CYC2. A disposable
cross-origin browser probe confirms that both child opener.focus and caller-side
self.focus leave Launcher hidden. Giving Launcher a unique browsing-context name
and targeting that existing context with window.open during the selection click
returns to Launcher without adding a page. This does not reopen Launcher through
a starter page or close Files. Browser refusal still requires a manual fallback.

Session code also reveals a concrete ownership gap: with an existing ID token,
perform may reserve no popup. A subsequent protected-resource authorization calls
authorizePopup without a handle. That library opens its own tab, but the session
never obtains/closes it. This explains a leftover callback page; it does not prove
every aspect of the maintainer's observed authentication exchange.

Retain popup handles for every interactive authorization, close owned UI on
success/failure, preserve noninteractive refusal and published-library OAuth
validation. Keep DEF18 Open. Verification must avoid workspace persistence and
the known forbidden JSON-in-Turtle fixtures; no user Pod access is needed.
