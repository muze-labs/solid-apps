# Replace workspace JSON-in-Turtle persistence with native RDF

Status: **Fixed and integrated in PR #3**. Retained from CYC-20261101-QG24H-2 as an explicit condition
of the maintainer's cycle acceptance on 2026-11-01. Acceptance does not resolve
this issue or waive the native Turtle rule.

The predecessor workspace-state.mjs wrote the main Pod snapshot and local cache as
RDF JSON literals, including a serialized baseline. Those structures hide
workspace/app state from ordinary RDF inspection and violate the maintainer's
native-format rule retained in SRC-20261101-QG24H-17 and AGENTS.md.

Replace the main workspace, app instances, resource links, UI/draft fields and
local persistence/baseline representation with native RDF statements. Preserve
unknown native RDF. SRC24 explicitly removes migration of unreleased JSON state
from the scope; old development data is left untouched, not imported. Do not hide the main model in another
serialized whole-workspace string or move it to JSON files as a workaround.

The sole authorized experiment is a separate, optional app-owned opaque state
string. It may contain JSON; the app interprets it and the broker preserves and
returns it unchanged. Keep the main state linked data. This is not a preferred
format: the maintainer considers embedded JSON ugly and expects objections.

Completion must demonstrate:

- Native RDF for main Pod state and local cache/baseline, with meaningful terms,
  resource IRIs and app-instance identity; no generic JSON snapshot literals.
- Data-preserving handling of existing state, unknown RDF, app ordering,
  identities and drafts. Reconnect secrets remain local and outside Pod exports.
- Exact round-trip of the optional app-owned opaque string without broker
  interpretation, under the narrowly authorized experiment.
- Conditional writes, post-205 validator refresh, real conflict detection and
  pending local edits preserved across reload, offline and authentication errors.
- Cross-origin selection, checkpoint/reconnect, close/restore and acknowledged
  Pod saving still work, within the existing JavaScript budget and UI rules.

If an appropriate native representation cannot be found for a concrete part,
explain the issue and resolve it with the maintainer before writing that format.
The native correction is implemented; no migration is included under SRC24. The starter page for closing
manually opened Launcher tabs remains a separate deferred feature.


## Implemented correction, 2026-11-01

Native Workspace/AppInstance nodes and app-owned state graphs replace Pod JSON
snapshots. The local cache stores current and acknowledged-baseline graphs as
native triples, including local-only reconnect keys and typed sync metadata.
Apps preserve full native state and profile drafts stay separate from profile
data. Unsupported structured fields, graph ownership and shared-node edits are
refused. The optional opaque string is preserved exactly and remains experimental.

The new native cache leaves old development records alone. Retired Pod targets
are refused and require a fresh workspace URL; there is no migration or silent
overwrite. Full unit/build and Chrome browser checks now run against native RDF,
including preservation, save/conflict/validator behavior and close/restore.
The issue remains in the repository with its original causal evidence. This
technical correction is not new whole-cycle human acceptance or merge approval.

[Verification EVD26](../evidence/EVD-20261101-QG24H-26.md) pins the corrected
implementation and records the complete checks, preservation cases, timing
regression, browser observations and manual retry instructions.


## Same-target recovery clarification

The maintainer rejected the fresh-URL workaround and approved discarding the
retired apps:snapshot property (SRC27). The reader now ignores unknown predicates
and the obsolete value; the Pod storage boundary removes only that property from
the current root during an explicit conditional native save. Other RDF remains
preserved, background close does not perform the discard, and no migration or
main-state JSON output is introduced. This supersedes the refusal/workaround
instructions above; the earlier verification remains pinned to its own version.


The maintainer subsequently merged the correction and final readable-Turtle
revision into main in PR #3. ACC32 records that integration/acceptance; the issue
remains here as historical evidence rather than an unresolved native-format gap.
