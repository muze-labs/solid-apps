# Replace workspace JSON-in-Turtle persistence with native RDF

Status: **Open**. Retained from CYC-20261101-QG24H-2 as an explicit condition
of the maintainer's cycle acceptance on 2026-11-01. Acceptance does not resolve
this issue or waive the native Turtle rule.

Current workspace-state.mjs writes the main Pod snapshot and local cache as
RDF JSON literals, including a serialized baseline. Those structures hide
workspace/app state from ordinary RDF inspection and violate the maintainer's
native-format rule retained in SRC-20261101-QG24H-17 and AGENTS.md.

Replace the main workspace, app instances, resource links, UI/draft fields and
local persistence/baseline representation with native RDF statements. Preserve
existing data during the transition. Do not hide the main model in another
serialized whole-workspace string or move it to JSON files as a workaround.

The sole authorized experiment is a separate, optional app-owned opaque state
string. It may contain JSON; the app interprets it and the broker preserves and
returns it unchanged. Keep the main state linked data. This is not a preferred
format: the maintainer considers embedded JSON ugly and expects objections.

Completion must demonstrate:

- Native RDF for main Pod state and local cache/baseline, with meaningful terms,
  resource IRIs and app-instance identity; no generic JSON snapshot literals.
- Data-preserving handling of existing state, unknown RDF, app ordering,
  identities and drafts. Reconnect secrets remain local and outside Pod exports.
- Exact round-trip of the optional app-owned opaque string without broker
  interpretation, under the narrowly authorized experiment.
- Conditional writes, post-205 validator refresh, real conflict detection and
  pending local edits preserved across reload, offline and authentication errors.
- Cross-origin selection, checkpoint/reconnect, close/restore and acknowledged
  Pod saving still work, within the existing JavaScript budget and UI rules.

If an appropriate native representation cannot be found for a concrete part,
explain the issue and resolve it with the maintainer before writing that format.
No implementation or migration is claimed here. The starter page for closing
manually opened Launcher tabs remains a separate deferred feature.
